# Secure Networking Module

A robust, message-exchange-based networking library that completely abstracts encryption, authentication, key management, and framing over TCP sockets. Designed for secure, asynchronous-style communication, it allows developers to focus entirely on application logic without managing cryptographic primitives or socket buffers.

## Core Features

*   **Exchange-Based Routing (`eid`):** Messages are tracked via Exchange IDs (`eid`). This allows multiplexed, non-blocking requests and responses over a single TCP connection, avoiding head-of-line blocking.
*   **Zero-Configuration Cryptography:** Fully transparent End-to-End Encryption (E2EE). The application layer never sees keys, nonces, or ciphertexts.
*   **Event-Driven Server Hooks:** Server logic is cleanly separated via an `on_exchange` callback that fires whenever a complete, authenticated message is received.
*   **Automated Key Provisioning:** First-time client connections use an out-of-band Admin Key (`.zip` format) to negotiate and provision long-term authentication keys automatically.
*   **Strict Password Policies:** Built-in `zxcvbn` integration ensures that passwords used for at-rest key encryption meet high entropy standards.

## Security Model

This module implements a defense-in-depth approach to both in-transit and at-rest data:

*   **In-Transit (Wire Protocol):** 
    *   Diffie-Hellman Key Exchange (X448) for Perfect Forward Secrecy (PFS).
    *   Ed448 signatures to prevent Man-in-the-Middle (MitM) attacks.
    *   AES-GCM for authenticated encryption of all payloads.
*   **At-Rest (Key Storage):**
    *   Long-term identity keys are encrypted on disk using AES-GCM.
    *   At-rest encryption keys are derived from user passwords using a slow Key Derivation Function (Argon2id: `mem_cost=512MB`, `time_cost=13`, `parallelism=1`) and unique salts.

## Installation / Requirements

*   `pyzmq` (ZeroMQ bindings for asynchronous socket management)
*   `zxcvbn` (Password strength estimation)
*   `cryptography` (Underlying crypto primitives)
*   `argon2-cffi` (Argon2 implementation for `Encryption.py`)
*   `blake3` (Fast cryptographic hash function for `Encryption.py`)
*   `numpy` (Utilized by helper functions in `util.py`)

## Usage Example

### 1. Server Setup

The server binds to a port and listens for incoming exchanges. It requires a strong password to protect its long-term keys on disk.

```python
from network import TCPServer

def handle_message(server, eid, data, client_id):
    print(f"Received: {data.decode('utf-8')}")
    # Reply using the same Exchange ID (eid) to route back to the specific client thread
    server.send(b"Message acknowledged!", eid=eid, client_id=client_id)

server = TCPServer(
    host="127.0.0.1", 
    port=8888, 
    password="SuperStrongPassword123!", 
    auth_key_dir="./server_keys",
    on_exchange=handle_message
)
```
### 2. Client Setup

The client connects to the server. On its first run, it requires the `admin_keys.zip` generated by the server. On subsequent runs, it uses its securely cached long-term key.

```python
from network import TCPClient

client = TCPClient(
    host="127.0.0.1", 
    port=8888,
    password="AnotherStrongPassword456!",
    auth_key="./client_auth.zip" # Replaced by an encrypted identity key after first run
)

# Send a message and get an Exchange ID (eid)
eid = client.send(b"Hello secure world!")

# Wait for the server's response tied to this specific eid
response = client.recv(eid, timeout=5.0)
if response:
    print(f"Server replied: {response.decode('utf-8')}")
```
## Architecture Notes

*   **Queue Management:** To prevent memory exhaustion attacks, the library enforces a maximum memory buffer (`MAX_QUEUE_BYTES`) per client. Misbehaving clients are automatically disconnected.
*   **Thread Safety:** Both `TCPServer` and `TCPClient` utilize background I/O threads and thread-safe queues. The `send()` and `recv()` methods are entirely thread-safe and can be called from anywhere in your application.
